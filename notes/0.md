# Agent安全沙箱

> 来源：<https://blog.gitcode.com/6f402553a05060eee4d2723980d903e2.html>  
> 原文标题：深入理解 NsJail：Linux 进程隔离工具详解

## 什么是 NsJail

NsJail 是一个基于 Linux Namespace 的轻量级进程隔离工具。它通过组合 Linux 内核提供的安全能力，为单个进程构建高隔离、可控资源的运行环境。相比传统容器方案，NsJail 更聚焦于"进程级隔离"，适合安全敏感场景。

> 深入理解 Namespace 机制 → [[nsjail 技术详解：Linux Namespace 与进程隔离原理]]

常见适用场景包括：安全研究、在线评测系统、服务沙箱化执行等。

## 核心能力

NsJail 主要依赖以下机制：

1. **命名空间隔离**：PID、Network、Mount、IPC、UTS、User Namespace。
2. **资源限制**：通过 cgroups 与 rlimits 限制 CPU、内存等资源。
3. **系统调用过滤**：通过 seccomp-bpf 约束可调用系统调用。→ [[seccomp-bpf 技术详解：系统调用过滤原理与实践]]
4. **权限裁剪**：通过 capabilities 机制最小化进程特权。

## 安装与基本用法

NsJail 通常以静态二进制分发，可直接运行。基础语法：

```bash
nsjail [选项] -- 要执行的命令 [命令参数]
```

## 运行模式

通过 `-M` 参数指定运行模式：

- `-Ml`：TCP 监听模式，等待连接后执行。
- `-Mo`：单次执行模式（默认），使用 `clone/execve`。
- `-Me`：直接执行模式，使用 `execve`。
- `-Mr`：循环执行模式，重复运行指定命令。

## 关键配置项

### 1) 文件系统隔离

- `-c, --chroot`：设置 jail 根目录。
- `-R, --bindmount_ro`：只读绑定挂载目录。
- `-B, --bindmount`：读写绑定挂载目录。
- `-T, --tmpfsmount`：挂载 tmpfs。

### 2) 用户与权限

- `-u, --user`：指定 jail 内用户。
- `-g, --group`：指定 jail 内用户组。
- `--keep_caps`：保留全部 capabilities。
- `--cap`：仅保留指定 capability（如 `CAP_PTRACE`）。

### 3) 网络配置

- `-p, --port`：监听 TCP 端口。
- `-I, --macvlan_iface`：创建 MACVLAN 接口。
- `-N, --disable_clone_newnet`：关闭网络命名空间隔离。

### 4) 资源限制

- `--rlimit_as`：限制地址空间。
- `--rlimit_cpu`：限制 CPU 时间。
- `--rlimit_nofile`：限制文件描述符数量。
- `--cgroup_mem_max`：限制最大内存。

### 5) 安全策略

- `-P, --seccomp_policy`：指定 seccomp-bpf 策略文件。
- `--seccomp_string`：直接传入 seccomp 策略。
- `--disable_no_new_privs`：禁用 `NO_NEW_PRIVS`（高风险）。

## 使用示例

### 基础隔离 Shell

```bash
nsjail -Mo --chroot / -- /bin/bash
```

### 隔离运行网络服务

```bash
nsjail -Ml --port 8080 --chroot /jail_root -- /usr/bin/python3 -m http.server
```

### 严格资源限制

```bash
nsjail -Mo --rlimit_as 256 --rlimit_cpu 10 --chroot / -- /bin/bash
```

### 自定义挂载集合

```bash
nsjail -Mo -R /lib -R /lib64 -R /usr -R /bin -R /etc -- /bin/bash
```

## 安全最佳实践

1. 遵循最小权限原则，只保留必要 capabilities。
2. 设置合理资源上限，避免资源耗尽攻击。
3. 使用 seccomp 策略收缩系统调用面。
4. 避免使用高风险参数（如 `--disable_no_new_privs`）。
5. 持续更新 NsJail，及时获取安全修复。

## 常见问题排查

1. **权限异常**：检查用户/组映射，尤其是 User Namespace 场景。
2. **挂载失败**：确认挂载目标在 chroot 内存在且路径正确。
3. **网络不可达**：检查网络命名空间、端口与网卡配置。
4. **资源限制过严**：结合业务实际调优 rlimits 与 cgroups。

## 小结

NsJail 适合构建“轻量但强约束”的进程沙箱。通过命名空间、资源限制、系统调用过滤与权限裁剪的组合，可以显著提升 Agent 执行环境的安全性与可控性。
