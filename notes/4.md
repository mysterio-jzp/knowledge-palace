> Landlock 是 Linux 5.13+ 引入的安全模块，允许一个进程**自己限制自己**的文件系统访问权限——不需要 root、不需要特权、不需要额外配置。在你项目里已经通过 Rust `landlock` crate 启用了。

## 1. 一句话理解

seccomp 限制"你能调用哪些 syscall"，Landlock 限制"你能访问哪些文件"。两者都是进程自己给自己上的锁，但维度不同：

```
进程运行中...
  ├── seccomp-bpf： 能调 read() 吗？ → 在白名单 → 放行
  └── Landlock：    read() 要读的文件在允许列表吗？ → 不在 → EACCES
```

## 2. 为什么需要 Landlock

### 2.1 nsjail 管外层，Landlock 管内层

nsjail 通过 Mount Namespace + chroot 限制了"能看到哪些目录"。但如果 nsjail 配置疏漏（比如某个目录忘了设为只读），进程仍然能写。Landlock 在进程**内部**再加一层锁：

```
┌─ nsjail ──────────────────────────────────────┐
│  Mount NS: /workspace 可写, 其他只读             │
│  ┌─ 用户进程 ──────────────────────────────┐   │
│  │  Landlock: 只允许读 /workspace/output/    │   │
│  │  即使 nsjail 允许写 /workspace/           │   │
│  │  Landlock 也不让写 /workspace/temp/       │   │
│  └──────────────────────────────────────────┘   │
└────────────────────────────────────────────────┘
```

**nsjail 是笼子，Landlock 是笼子里的镣铐。**

### 2.2 和其他机制的区别

| 机制 | 谁控制 | 限制什么 | 需要特权？ |
|------|--------|---------|-----------|
| **nsjail namespace** | 外部（父进程） | 资源视图：能看到什么 | 是（clone 需要 CAP_SYS_ADMIN） |
| **seccomp-bpf** | 自身 | syscall 调用：能做什么操作 | 是（prctl 需要 no_new_privs） |
| **Landlock** | 自身 | 文件路径：能访问哪些文件 | **否**（非特权进程可直接调用） |
| **rlimit** | 外部或自身 | 资源用量：能用多少 | 否 |

**Landlock 的独特价值**：它是唯一一个"进程自己给自己上锁且不需要任何特权"的机制。

## 3. Landlock 工作原理

### 3.1 核心概念：Ruleset（规则集）

Landlock 的所有操作围绕一个 `Ruleset` 展开：

```rust
// 1. 创建一个空的规则集，声明要控制哪些操作
let ruleset = Ruleset::default()
    .handle_access(AccessFs::from_all())?  // 我要接管所有文件访问
    .create()?;                            // 创建规则集
```

`AccessFs` 是 Landlock 定义的访问权限类型：

| 权限 | 含义 | 示例操作 |
|------|------|---------|
| `Execute` | 执行文件 | `execve()` |
| `WriteFile` | 写入文件 | `write()` |
| `ReadFile` | 读取文件 | `read()` |
| `ReadDir` | 读取目录 | `readdir()`、`ls` |
| `RemoveDir` | 删除目录 | `rmdir()` |
| `RemoveFile` | 删除文件 | `unlink()` |
| `MakeChar` | 创建设备文件 | `mknod()` |
| `MakeDir` | 创建目录 | `mkdir()` |
| `MakeReg` | 创建普通文件 | `creat()` |
| `MakeSock` | 创建 socket 文件 | `bind()` AF_UNIX |
| `MakeFifo` | 创建 FIFO | `mkfifo()` |
| `MakeSym` | 创建符号链接 | `symlink()` |
| `Refer` | 通过路径引用文件/目录 | `link()`、`rename()` |
| `Truncate` | 截断文件 | `truncate()`、`ftruncate()` |

### 3.2 添加规则：允许 vs 拒绝

Landlock 采用**默认拒绝 + 白名单**模式：

```rust
// 2. 添加允许访问的路径
ruleset.add_rule(PathBeneath::new(
    "/workspace/output",           // 只允许这个目录
    AccessFs::from_read()          // 且只允许读
))?;

ruleset.add_rule(PathBeneath::new(
    "/usr/lib",                     // 允许读取系统库
    AccessFs::from_read() | AccessFs::Execute  // 读 + 执行
))?;

// 3. 锁定！规则生效，不可撤销
ruleset.restrict_self()?;

// 此后：
// ✅ read("/workspace/output/data.txt") → 允许
// ❌ write("/workspace/output/data.txt") → EACCES（只允许读）
// ❌ read("/etc/passwd") → EACCES（不在白名单）
// ❌ open("/workspace/output/new.txt", O_CREAT) → EACCES（不允许创建）
```

> **关键特性**：`restrict_self()` 是**单向不可逆**的。一旦调用，当前进程及其所有子进程的 Landlock 规则永久锁定，无法放宽。这是安全设计——防止被 sandbox 的代码自己解除限制。

### 3.3 规则继承

Landlock 的规则是**叠加且收窄**的：

```
父进程 Landlock: allow /workspace/
    │
    ├── 子进程 A 追加: allow /workspace/output/ (更窄，OK)
    │
    └── 子进程 B 追加: allow /home/ (父不允许，不允许放宽 ✗)
```

子进程只能比父进程更严格，不能放宽。这确保了纵深防御中的每一层都不会被内层推翻。

## 4. 在你的 Rust 项目中使用

### 4.1 依赖

```toml
# Cargo.toml
[dependencies]
landlock = "0.4"
```

### 4.2 典型用法：starmerx-fileio 中的 sandbox.rs

你的项目里 `sandbox.rs` 用 Landlock 做了文件系统沙箱。核心逻辑：

```rust
use landlock::{ABI, AccessFs, Ruleset, PathBeneath};
use std::path::Path;

/// 为当前进程启用 Landlock 文件系统沙箱
/// 
/// 只允许访问白名单中的路径，规则一旦启用不可撤销。
pub fn enable_fs_sandbox(allowed_paths: &[&Path]) -> Result<(), Box<dyn std::error::Error>> {
    // 检查内核是否支持 Landlock
    let abi = ABI::V5; // Landlock ABI v5 (Linux 6.7+, 支持网络限制)
    
    // 创建规则集：我要控制所有文件访问类型
    let mut ruleset = Ruleset::default()
        .set_compatibility(abi)
        .handle_access(AccessFs::from_all())?
        .create()?;
    
    // 添加允许路径（只读）
    for path in allowed_paths {
        ruleset.add_rule(PathBeneath::new(
            path,
            AccessFs::from_read() | AccessFs::Execute  // 只读 + 可执行
        ))?;
    }
    
    // 锁定规则，永久生效
    ruleset.restrict_self()?;
    
    tracing::info!("Landlock sandbox activated: {} allowed paths", allowed_paths.len());
    Ok(())
}
```

### 4.3 跟你当前 nsjail 配置的配合

```
nsjail（外层）                          Landlock（内层，Rust 进程内）
─────────────────────────────         ───────────────────────────
允许写 /workspace                     只允许读 /workspace/output
允许读 /usr/lib                       允许读 /usr/lib + 执行
允许读 /bin                           不允许 /bin（不进白名单）
允许读 /opt/opencode/runtime          允许读 /opt/opencode/runtime

实际生效 = nsjail 允许 ∩ Landlock 允许
         = 两层白名单取交集
```

这就是你在 Python → Rust 文档里写的 **"纵深防御而不只靠外层 nsjail"**。

## 5. Landlock ABI 版本演进

| ABI | 内核版本 | 新增能力 |
|-----|---------|---------|
| V1 | 5.13 | 基本文件访问控制（ReadFile, WriteFile, Execute 等） |
| V2 | 5.19 | `Refer` 权限（控制 link/rename 等路径引用操作） |
| V3 | 6.0 | `Truncate` 权限（截断文件） |
| V4 | 6.3 | `ioctl` 设备控制 |
| V5 | 6.7 | 网络访问控制（TCP 端口绑定/连接限制） |

检查当前内核支持的 ABI：

```rust
use landlock::ABI;

println!("内核支持的最高 Landlock ABI: {:?}", ABI::current());
```

## 6. Landlock vs seccomp：什么时候用哪个

| | Landlock | seccomp-bpf |
|---|---------|------------|
| **控制粒度** | 文件路径 + 操作类型 | syscall 编号 + 参数 |
| **配置复杂度** | 低（指定路径和白名单权限） | 中（需要了解 syscall 编号） |
| **"能读 /etc/passwd 吗"** | ✅ 直接限制 | ❌ 读文件走通用的 read()，seccomp 分不出文件 |
| **"能调 reboot() 吗"** | ❌ 不负责 syscall 过滤 | ✅ 精确拦截 |
| **需要特权** | 否 | 否（设置时需要 no_new_privs） |
| **不可逆** | ✅ 是 | ✅ 是 |
| **父子继承** | 叠加收窄 | 子进程继承 |

**结论**：Landlock 和 seccomp 管不同的事，叠起来用。你项目里就是 **nsjail（外层） + Landlock（文件） + seccomp 留给未来**。

## 7. 踩坑与限制

### 7.1 内核版本要求

```bash
# 检查内核是否支持 Landlock
uname -r
# 需要 >= 5.13

# 检查 Landlock 是否已编译进内核
cat /boot/config-$(uname -r) | grep CONFIG_SECURITY_LANDLOCK
# CONFIG_SECURITY_LANDLOCK=y
```

### 7.2 Docker 容器内使用

Docker 默认 seccomp profile 可能拦截了 Landlock 的 `landlock_create_ruleset()` 和 `landlock_restrict_self()` syscall。如果遇到 `ENOSYS`：

```yaml
# docker-compose.yml
services:
  sandbox:
    security_opt:
      - seccomp:unconfined   # 或自定义 profile 放行 Landlock syscall
```

### 7.3 Landlock 不能限制它——已经打开的文件描述符

`restrict_self()` 之前通过 `open()` 拿到的 fd，在限制之后依然可读写。所以规则要在**打开任何用户文件之前**设置。

### 7.4 macOS 不可用

Landlock 是 Linux 专属。开发环境在 macOS 上时，`landlock` crate 的 `restrict_self()` 会返回错误，需要做平台判断：

```rust
#[cfg(target_os = "linux")]
{
    enable_fs_sandbox(&allowed_paths)?;
}
#[cfg(not(target_os = "linux"))]
{
    tracing::warn!("Landlock not available on this platform, skipping sandbox");
}
```
