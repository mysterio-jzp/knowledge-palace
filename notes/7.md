## 1. 背景与目标

### 1.1 问题描述

在使用 nsjail 的 **one-shot 模式**（`mode: once`）时，每次执行命令都需要：

- `clone()` 创建新进程并附加 namespace（PID、Mount、IPC 等），内核态开销 ~2-5ms
- `mount` 绑定必要的系统目录（`/bin`、`/usr`、`/lib*`、`/workspace`）
- `chroot` 切换到 jail 根目录
- 命令执行完毕后，以上隔离环境随进程退出而销毁

如果每次请求还需要动态挂载不同目录（如多租户的 `/srv/sandboxes/<username>`），one-shot 是唯一选项——监听模式的 mount 表固定，无法中途追加 bind mount（详见 [[nsjail 监听模式完整技术文档#2.1.1 监听模式的适用边界（重要）|适用边界]]）。

**对于不需要动态挂载、但需要频繁执行命令的场景，这种重复初始化的开销不可接受。**

### 1.2 解决方案

使用 nsjail 的 **监听模式**（`mode: l`，即 listener），让沙箱作为常驻服务运行：

- **初始化一次**：namespace + mount + chroot 在启动时完成，后续命令不再重复
- **反复使用**：通过 Unix Socket 向沙箱发送命令，nsjail 在已有 jail 中 `fork` 子进程执行
- **资源高效**：消除重复的 `clone` + `mount` 开销，每次执行仅 fork（亚毫秒级）

### 1.3 最终效果

```
传统 one-shot 模式：
  执行 100 条命令 = 100 次初始化 + 100 次执行 + 100 次销毁
  耗时：初始化开销 × 100

监听模式：
  执行 100 条命令 = 1 次初始化 + 100 次执行
  耗时：初始化开销 × 1
```

## 2. 核心概念解释

### 2.1 nsjail 的运行模式

nsjail 支持多种运行模式，通过 `mode` 参数指定：

| 模式值 | 含义 | 行为 | 适用场景 |
|--------|------|------|---------|
| `once` | 单次执行 | 隔离 → 执行命令 → 退出 | 偶尔执行 |
| `l` | 监听模式（listener） | 初始化 → 常驻等待 → 接收命令 → 执行 → 继续等待 | **频繁执行** |
| `execve` | 直接替换 | 隔离后直接 execve 替换当前进程 | 作为 init 进程 |

本文档专注于 **监听模式（mode: l）**。

### 2.1.1 监听模式的适用边界（重要）

> ⚠️ 监听模式不是银弹，你的场景如果命中以下条件，必须走 one-shot。

**什么时候不该用监听模式：**

| 场景 | 为什么不行 |
|------|-----------|
| **每次请求需挂载不同目录** | Mount Namespace 创建后 mount 表就固定了。比如多租户场景，不同 `username` 需要 `-B /srv/sandboxes/alice:/workspace`，监听模式做不到动态切换 |
| **每次请求需不同网络拓扑** | 网络配置（macvlan、iptables 规则）在启动时一次性设定，无法按请求热更新 |
| **需要不同资源限制** | cgroup 限制在 jail 创建时敲定，不同请求想用不同的内存/CPU 上限 → 不行 |
| **需要隔离级别不同** | 有的请求要 `clone_newnet: true` 有的不要 → 监听模式是统一的 |

**实际判断准则：**

```
你的场景是否每次请求共享完全相同的：
  ├── 文件系统挂载（mount binds）
  ├── 网络配置（IP/防火墙/DNS）
  └── 资源限制（cgroup/rlimit）
      │
      ├── 全是 → 监听模式合适
      └── 有一个不同 → one-shot，别犹豫
```

**当前项目的结论**：`starmerx-fileio` 按 `username` 动态挂载 `/srv/sandboxes/<username>`，**属于"有一个不同"**，因此 one-shot + Rust 二进制是正确方案。冷启动优化（2-3ms 的 Rust execve）已经抹掉了 one-shot 的主要开销。

### 2.2 Unix Socket（Unix 域套接字）— 监听模式的通信通道

> 回顾 2.1：监听模式下 nsjail 常驻等待外部命令。命令怎么传进来？

nsjail 监听模式通过 **Unix Socket** 接收外部命令。Unix Socket 是一种**本机进程间通信**机制，表现为文件系统上的一个特殊文件（以 `s` 开头）。nsjail 启动后在这个文件上"监听"，外部通过 `nsjail-run` 工具连上去发命令。

- 比喻：就像公司内部的电话专线，只有公司内的人能用，外人打不进来
- 与 TCP 端口的区别：Unix Socket 不经过网络协议栈，速度更快，也更安全（不会被外部网络扫描到）
- 文件路径示例：`/run/nsjail.sock`

> **套接字**（Socket）：进程间通信的端点，可以理解为"通信插口"。可以在本机进程之间，也可以跨网络。
> **Unix 域套接字**（Unix Domain Socket）：限定在同一台机器内的套接字，不走网络栈，比 TCP 更高效。

### 2.3 nsjail-run 工具

`nsjail-run` 是 nsjail 附带的**客户端工具**，用于向监听模式的 nsjail 沙箱发送命令。

- 作用：连接到 nsjail 的 Unix Socket，发送要执行的命令，等待并返回执行结果
- 类比：就像给沙箱打电话说"帮我执行这条命令"

### 2.4 守护进程（Daemon）

守护进程是指在后台持续运行的进程，没有控制终端，通常在系统启动时启动，关闭时停止。

- 发音：[ˈdiːmən]（迪蒙）
- nsjail 监听模式下的沙箱就是一个守护进程
- 特点：长期存活、等待请求、处理完毕继续等待

### 2.5 控制组（cgroup）

cgroup（Control Group）是 Linux 内核的资源限制机制，可以限制进程组的 CPU、内存、磁盘 I/O 等资源使用。

- nsjail 可以使用 cgroup 限制沙箱内的资源使用
- 在监听模式下，所有通过沙箱执行的命令共享同一个 cgroup 限制

### 3.2 命令执行流程

```
外部调用 nsjail-run
        │
        ▼
连接到 /run/nsjail.sock
        │
        ▼
发送命令字符串
        │
        ▼
nsjail 主进程接收命令
        │
        ▼
在已初始化的隔离环境中 fork 子进程
        │
        ▼
子进程执行命令
        │
        ├── stdout → 通过 socket 返回
        ├── stderr → 通过 socket 返回
        └── 退出码 → 通过 socket 返回
        │
        ▼
nsjail-run 输出结果并退出
        │
        ▼
沙箱主进程继续等待下一条命令
```

## 4. 前置条件

### 4.1 软件版本要求

| 软件 | 最低版本 | 推荐版本 | 说明 |
|------|---------|---------|------|
| Docker | 20.10 | 24.0+ | 容器运行时 |
| nsjail | 3.0 | 3.4+ | 沙箱工具，需支持监听模式 |
| dnsmasq | 2.80 | 2.90+ | DNS 过滤服务 |
| Python | 3.7 | 3.10+ | 客户端调用 |
| Linux 内核 | 4.0+ | 5.10+ | 需支持网络命名空间 |

### 4.2 Linux 能力（Capabilities）

Docker 容器必须拥有 `NET_ADMIN` 能力：

```bash
docker run --cap-add=NET_ADMIN ...
```

**什么是 Linux 能力？**  
Linux 将 root 的权限拆分成多个细粒度的"能力"，`NET_ADMIN` 是其中之一，允许执行网络管理操作（如创建虚拟网卡、设置 iptables 规则）。相比直接给 root 权限，这是一种更安全的做法。

### 5.2 Dockerfile 编写

```dockerfile
# ============================================
# 沙箱 Docker 镜像
# 基于 Ubuntu 22.04 LTS
# ============================================

FROM ubuntu:22.04

# 设置非交互式安装，避免 apt 安装时弹出配置界面
ENV DEBIAN_FRONTEND=noninteractive

# 更新软件源并安装必要工具
RUN apt-get update && apt-get install -y \
    # ---- 核心工具 ----
    nsjail \                         # 沙箱隔离工具
    dnsmasq \                        # DNS 过滤服务
    iptables \                       # 防火墙工具
    iproute2 \                       # 网络管理工具（提供 ip 命令）
    # ---- 测试工具 ----
    curl \                           # HTTP 请求测试
    dnsutils \                       # DNS 查询测试（提供 dig 命令）
    # ---- Python 运行时（如果沙箱需要执行 Python 代码）----
    python3 \
    python3-pip \
    # ---- 其他工具 ----
    procps \                         # 进程查看工具（ps 命令）
    netcat-openbsd \                 # 网络调试工具
    # ---- 清理 ----
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

# 创建 nsjail 专用的非特权用户
# 这是一个安全措施：沙箱内的进程不以 root 身份运行
# -m: 创建家目录 /home/jailuser
# -s /bin/bash: 指定登录 shell
RUN useradd -m -s /bin/bash jailuser

# 创建 chroot 根目录
# chroot（Change Root）：改变进程的根目录，限制文件系统访问范围
RUN mkdir -p /jail

# ---- 复制配置文件到镜像内 ----

# nsjail 配置
COPY nsjail-listen.cfg /nsjail-listen.cfg

# 沙箱初始化脚本（放入 jail 目录，因为 nsjail chroot 后只能看到 /jail 下的文件）
COPY init-and-listen.sh /jail/init-and-listen.sh
RUN chmod +x /jail/init-and-listen.sh

# dnsmasq 配置
COPY dnsmasq-whitelist.conf /jail/etc/dnsmasq-whitelist.conf

# 应用代码（放入 jail 目录）
COPY app/ /jail/app/

# 启动脚本
COPY start-sandbox.sh /start-sandbox.sh
RUN chmod +x /start-sandbox.sh

# 创建 Unix Socket 目录
RUN mkdir -p /run

# ---- 元信息 ----
LABEL description="nsjail 监听模式沙箱 - 支持网络隔离和域名白名单"
LABEL version="1.0"

# 默认启动命令
CMD ["/bin/bash", "/start-sandbox.sh"]
```

### 5.3 nsjail 监听模式配置文件

创建 `nsjail-listen.cfg`：

```
# ============================================
# nsjail 监听模式配置文件
# ============================================

# --- 运行模式 ---
# l = listener（监听模式），沙箱启动后常驻等待命令
mode: l

# --- 文件系统隔离 ---
# chroot 根目录，沙箱内只能看到这个目录下的文件
chroot: "/jail"

# 挂载 proc 文件系统（提供进程信息）
# 某些程序需要 /proc 才能正常运行
mount_proc: true

# --- 用户权限 ---
# 以非 root 用户运行，提高安全性
user: "jailuser"
group: "jailuser"

# --- 网络隔离 ---
# 创建独立的网络命名空间
clone_newnet: true

# 基于宿主的 eth0 创建 macvlan 虚拟网卡
# macvlan0 在沙箱内可见，拥有独立 IP
macvlan_iface: "eth0"

# --- 安全加固 ---
# 禁止访问 /proc（更严格的安全配置，按需开启）
# disable_proc: true

# 禁止沙箱内获取新的 Linux 能力
# no_new_privs: true

# --- 资源限制（可选）---
# 限制内存使用
# cgroup_mem_max: 536870912    # 512MB

# 限制 CPU 使用（核心数 × 100000）
# cgroup_cpu_ms_per_sec: 50000  # 限制为 0.5 核

# 限制进程数
# cgroup_pids_max: 50

# --- 监听配置 ---
# 监听的 Unix Socket 路径
# 外部通过这个路径向沙箱发送命令
listen_uds: "/run/nsjail.sock"

# --- 初始化进程 ---
# 沙箱启动时执行的命令
# 这里执行网络初始化脚本，然后常驻等待
exec_bin: "/bin/bash"
exec_args: ["/init-and-listen.sh"]

# --- 日志 ---
# 日志级别：DEBUG, INFO, WARNING, ERROR, FATAL
log_level: INFO

# 日志输出文件（可选，不设置则输出到 stderr）
# log_file: "/var/log/nsjail.log"
```

### 5.4 沙箱初始化脚本

创建 `init-and-listen.sh`（放入 `/jail/init-and-listen.sh`）：

```bash
#!/bin/bash
# ============================================
# nsjail 监听模式 - 沙箱初始化脚本
# 功能：
#   1. 保持进程存活（nsjail 以此进程为 init）
#   2. nsjail 通过 Unix Socket 接收命令后 fork 子进程执行
#
# 注意：网络隔离已在部署层（setup_netns.sh）完成，
#       本脚本不涉及任何网络配置。
# ============================================

set -euo pipefail

echo "[sandbox-init] nsjail 监听模式已就绪，等待命令..."
echo "[sandbox-init] Socket 路径: /run/nsjail.sock"

# 关键：保持进程运行，否则 nsjail 会认为 init 结束而退出
# nsjail 主进程在后台监听 socket，此脚本作为 jail 内的 PID 1 必须存活
exec sleep infinity
```

## 6. Python 集成：向沙箱发送命令

### 6.1 基础调用方式

最简单的调用方式是使用 Python 的 `subprocess` 模块执行 `nsjail-run`：

```python
import subprocess
from typing import Tuple, Optional


def sandbox_exec(command: str, timeout: int = 30) -> Tuple[int, str, str]:
```

"""

import subprocess
import json
import shlex
from typing import List, Dict, Optional, Tuple
from dataclasses import dataclass
from pathlib import Path


@dataclass
class SandboxResult:
    """沙箱执行结果"""

    returncode: int       # 退出码
    stdout: str           # 标准输出
    stderr: str           # 标准错误
    timed_out: bool       # 是否超时
    command: str          # 执行的命令

    @property
    def success(self) -> bool:
        """命令是否执行成功（退出码为 0 且未超时）"""
        return self.returncode == 0 and not self.timed_out

    def to_dict(self) -> dict:
        """转为字典"""
        return {
            "returncode": self.returncode,
            "stdout": self.stdout,
            "stderr": self.stderr,
            "timed_out": self.timed_out,
            "command": self.command,
        }

    def to_json(self) -> str:
        """转为 JSON 字符串"""
        return json.dumps(self.to_dict(), ensure_ascii=False, indent=2)


class SandboxClient:
    """
    nsjail 沙箱客户端

    使用示例:
        client = SandboxClient("/run/nsjail.sock")
        result = client.execute("python3 /app/main.py")
        if result.success:
            print(result.stdout)
    """

    def __init__(self, socket_path: str = "/run/nsjail.sock"):
        """
        初始化沙箱客户端

        参数:
            socket_path: nsjail 监听的 Unix Socket 路径
        """
        self.socket_path = Path(socket_path)

        # 检查 socket 是否存在
        if not self.socket_path.exists():
            raise FileNotFoundError(
                f"沙箱 socket 不存在: {self.socket_path}\n"
                f"请确保 nsjail 监听模式已启动"
            )

        # 检查是否是 socket 文件
        if not self.socket_path.is_socket():
            raise ValueError(
                f"路径不是 Unix Socket: {self.socket_path}"
            )

    def execute(
        self,
        command: str,
        timeout: int = 30,
        env: Optional[Dict[str, str]] = None,
        workdir: Optional[str] = None,
    ) -> SandboxResult:
        """
        在沙箱中执行命令

        参数:
            command: 要执行的命令（字符串形式，会自动处理引号）
            timeout: 超时时间（秒）
            env: 环境变量字典
            workdir: 工作目录

        返回:
            SandboxResult 对象
        """
        # 构建 nsjail-run 命令
        cmd_parts = ["nsjail-run", "-s", str(self.socket_path)]

        # 设置工作目录
        if workdir:
            cmd_parts.extend(["--chdir", workdir])

        # 设置环境变量
        if env:
            for key, value in env.items():
                cmd_parts.extend(["--env", f"{key}={value}"])

        # 分隔符和实际命令
        cmd_parts.append("--")
        cmd_parts.append(command)

        timed_out = False

        try:
            # 执行命令
            result = subprocess.run(
                cmd_parts,
                capture_output=True,
                text=True,
                timeout=timeout,
            )

            return SandboxResult(
                returncode=result.returncode,
                stdout=result.stdout,
                stderr=result.stderr,
                timed_out=False,
                command=command,
            )

        except subprocess.TimeoutExpired:
            timed_out = True
            return SandboxResult(
                returncode=-1,
                stdout="",
                stderr=f"命令执行超时 (>{timeout}秒)",
                timed_out=True,
                command=command,
            )

        except FileNotFoundError:
            raise RuntimeError(
                "未找到 nsjail-run 命令，请确保 nsjail 已安装且已加入 PATH"
            )

        timeout: int = 30,
