> 理解沙箱网络隔离的前置知识。这些是 Linux 中最常见的网络接口类型，你的 netns + nftables 方案全程依赖它们。

## 1. eth0 — 物理网卡

```
┌─────────────────────────────────────┐
│              你的电脑                  │
│                                     │
│  ┌───────┐                          │
│  │ eth0  │──── 网线 / WiFi ──── 路由器 ── 互联网
│  └───────┘                          │
│                                     │
└─────────────────────────────────────┘
```

**eth0 是你电脑对外通信的物理出口。** 就像你家的门牌号——别人要寄快递给你，得写这个地址；你要出去，也得从这个门走。

| 属性 | 说明 |
|------|------|
| **全称** | Ethernet Interface 0（第一个以太网接口） |
| **本质** | 物理网卡的内核抽象 |
| **IP 地址** | 如 `192.168.1.10`，由 DHCP 分配或静态配置 |
| **MAC 地址** | 硬件出厂自带，如 `aa:bb:cc:dd:ee:ff` |
| **对应设备** | 实体网线口 / WiFi 芯片 |

```bash
# 查看你机器上的 eth0
ip addr show eth0
# 2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500
#     inet 192.168.1.10/24 brd 192.168.1.255 scope global eth0

# Docker 容器里的 eth0 是虚拟的，但角色一样——都是容器对外的"门"
```

> **macOS 例外**：苹果设备不用 `eth0` 命名，无线网卡叫 `en0`。但概念完全一样。

## 2. lo — 本地回环接口

```
┌─────────────────────────────────────┐
│              你的电脑                  │
│                                     │
│  ┌──────┐                           │
│  │  lo  │ ← 127.0.0.1               │
│  └──────┘    （自己连自己）            │
│                                     │
│  进程 A ──→ 127.0.0.1:8080 ──→ 进程 B │
│  （都是本机的进程）                     │
└─────────────────────────────────────┘
```

**lo 是进程和自己这台机器上的其他进程通信用的。** 数据不出网卡，不走网络协议栈的下半段（不需要 ARP、不需要路由），纯内存拷贝，极快。

| 属性 | 说明 |
|------|------|
| **全称** | Loopback Interface |
| **IP** | 固定 `127.0.0.1`（IPv4）和 `::1`（IPv6） |
| **流量** | 只在本机内部流转，永远不经过物理网卡 |
| **速度** | 极快（纯内存操作，无网络延迟） |
| **用途** | 本机进程间通信：数据库连接 `localhost:3306`、本地 Web 开发 `localhost:3000` |

```bash
# 每台机器都有 lo，无需配置，系统自带
ip addr show lo
# 1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536
#     inet 127.0.0.1/8 scope host lo

# ping 自己，永远通
ping 127.0.0.1   # 0.02ms — 比真正网络快几百倍
```

**和沙箱的关系**：每个新创建的 netns 默认也只有 lo——意味着盒子里的进程可以自己和自己通信，但和外界完全隔绝。

## 3. veth pair — 虚拟网线

```
            veth pair（一对）
    ┌─────────────────────────────┐
    │                             │
    ▼                             ▼
┌───────┐                     ┌───────┐
│veth_h │◄───────────────────►│veth_j │
│ .1    │    像一根网线的两端     │ .2    │
└───────┘                     └───────┘
    │                             │
    ▼                             ▼
 宿主机 netns               sandbox netns
```

**veth pair 是一对虚拟以太网设备，成对出现，像一根网线的两端。** 一端插在 namespace A，另一端插在 namespace B，数据从一端进、另一端出。

| 属性 | 说明 |
|------|------|
| **全称** | Virtual Ethernet Pair |
| **本质** | 内核中的一对虚拟网卡，数据在它们之间直接转发 |
| **关键特性** | **成对创建**，不能单独存在；一端收到数据，另一端立刻收到 |
| **用途** | 连接两个 network namespace |

### 3.1 为什么需要 veth pair

netns 创建后默认只有 lo，和外界完全不通。要让盒子里能上网，需要在宿主机 netns 和沙箱 netns 之间搭一座桥——veth pair 就是这座桥：

```bash
# 1. 创建一根"虚拟网线"
ip link add veth_h type veth peer name veth_j
#    ┌──────┐      ┌──────┐
#    │veth_h│◄────►│veth_j│   一对，同时出生
#    └──────┘      └──────┘

# 2. 把 veth_j 端移入沙箱 netns
ip link set veth_j netns sandbox
#    宿主机 netns              sandbox netns
#    ┌──────┐                ┌──────┐
#    │veth_h│◄── veth pair ──►│veth_j│
#    └──────┘                └──────┘

# 3. 分别给两端配 IP 并启用
ip addr add 10.200.0.1/30 dev veth_h
ip netns exec sandbox ip addr add 10.200.0.2/30 dev veth_j
ip link set veth_h up
ip netns exec sandbox ip link set veth_j up

# 4. 盒子里加默认路由 — 所有流量走 veth_j 出去
ip netns exec sandbox ip route add default via 10.200.0.1
```

### 3.2 数据怎么流

```
沙箱内 ping 8.8.8.8
    │
    ▼
查路由表: default via 10.200.0.1 → 走 veth_j
    │
    ▼
veth_j 发出 → 经过 veth pair → veth_h 收到（出现在宿主机 netns）
    │
    ▼
宿主机路由: 8.8.8.8 → 走 eth0 → 互联网
    │
    ▼
回包: eth0 → 宿主机 netns → veth_h → veth pair → veth_j → 沙箱内进程
```

**一句话：veth pair 就是 namespace 之间的"网线"。**

### 3.3 在你的项目里

```
宿主机 netns               starmerx_jail netns
┌────────────┐            ┌──────────────┐
│            │            │              │
│  veth_j_h  │◄─ pair ──►│  veth_j_j    │
│  10.200.0.1│            │  10.200.0.2  │
│            │            │              │
│  代理 :8888│            │  nftables:   │
│            │            │  只允许 →     │
│            │            │  :53 + :8888 │
└────────────┘            └──────────────┘
```

## 4. 三者关系一张图

```
物理机 / 宿主机 netns
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  eth0 (192.168.1.10)                                      │
│    │                                                     │
│    ├── 互联网 ← 真正的物理出口                              │
│    │                                                     │
│  lo (127.0.0.1)                                          │
│    ├── 本机进程间通信，不出网卡                              │
│    │                                                     │
│  veth_j_h (10.200.0.1)                                   │
│    │                                                     │
│    └── veth pair ──────────────────────────────┐         │
│                                                 │         │
└─────────────────────────────────────────────────│─────────┘
                                                  │
                    ┌─────────────────────────────┘
                    ▼
          sandbox netns
          ┌──────────────────────────────┐
          │                              │
          │  lo (127.0.0.1)               │
          │    ├── sandbox 内进程间通信     │
          │                              │
          │  veth_j_j (10.200.0.2)        │
          │    ├── 唯一对外通道            │
          │    └── 经 veth pair → 宿主机   │
          │                              │
          │  路由: default via 10.200.0.1  │
          │  nftables: DROP all except     │
          │    :53 + :8888                │
          └──────────────────────────────┘
```

## 5. 速查对比

| | eth0 | lo | veth pair |
|---|------|-----|-----------|
| **是什么** | 物理网卡/主出口 | 本机回环，自己连自己 | 一对虚拟网卡，成对出现 |
| **流量去哪** | 出机器，经路由器到互联网 | 不出机器，纯内存 | 从一端进、另一端出 |
| **在 sandbox 中存在吗** | ❌ 默认没有 | ✅ 默认有 | ✅ 手动创建后才有 |
| **典型 IP** | `192.168.1.10` | `127.0.0.1` | `10.200.0.x`（自定义） |
| **你的项目中** | 宿主机用它出外网 | sandbox 内进程间通信 | 连接宿主机和 sandbox netns |
