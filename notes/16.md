## 什么是 Agent

Agent（智能体）不是单一模型，而是一个**由 LLM 驱动的自主系统**——它能感知环境、制定计划、调用工具、在循环中反思与修正，最终完成目标。

与传统的"输入→输出"式 LLM 调用不同，Agent 的核心差异在于 **自主决策循环**（Agentic Loop）：模型不再是一次性给出答案，而是像人一样"思考 → 行动 → 观察 → 再思考"，在迭代中逼近目标。

## Agent 核心能力模块

业界对 Agent 架构有多套成熟框架，以下是最广泛认可的四大核心能力（参考 Lilian Weng / Andrew Ng / Anthropic 等主流观点）：

### 1. 推理与规划 (Reasoning & Planning)

Agent 的"大脑"。面对复杂任务时，不是一步到位给答案，而是先拆解子任务、再按路径执行。

关键技术：
- **Chain-of-Thought (CoT)**：让模型在给出结论前先进行分步推理
- **ReAct**：推理 (Reasoning) 与行动 (Action) 交替进行
- **Plan-and-Execute**：先规划再执行，适合长链条任务
- **Tree-of-Thought / Graph-of-Thought**：多路径探索 + 回溯，比线性 CoT 更鲁棒

### 2. 记忆系统 (Memory)

Agent 用来"记住"上下文的机制，分三层：

| 类型 | 作用 | 典型实现 |
|------|------|----------|
| **短期记忆** | 当前对话上下文 | 上下文窗口、滑动窗口压缩 |
| **长期记忆** | 跨会话知识沉淀 | 向量数据库 (Pinecone/Milvus)、知识图谱 |
| **工作记忆** | 任务执行中间状态 | 草稿本 (scratchpad)、文件系统、状态机 |

记忆不是存得越多越好——检索精度、时效性、隐私性三者需要权衡。

### 3. 工具使用 (Tool Use / Function Calling)

让 LLM 突破纯文本的边界，与外部世界交互。

- **Function Calling**：模型输出结构化 JSON 触发外部 API
- **代码执行**：Python/Shell 沙箱中运行代码
- **RAG（检索增强生成）**：从外部知识库检索后注入上下文
- **Browser / MCP / ACP**：通过标准化协议调用外部工具

工具调用的核心挑战不是"能调"，而是**什么时候调、调哪个、调完怎么用**——这本质上是规划与推理的延伸。

### 4. 多 Agent 协同 (Multi-Agent Collaboration)

当单个 Agent 难以覆盖全部场景时，多个 Agent 分工协作。

- **垂直分工**：不同 Agent 负责不同领域（编码 Agent、测试 Agent、文档 Agent）
- **水平协作**：多个同构 Agent 并行处理子任务后汇总
- **拓扑模式**：顺序链、层级树、动态路由、辩论式
- **协调机制**：消息传递 vs 共享黑板 vs 中心编排器

> 参考 Anthropic 的观点：从简单工作流开始，只在确有必要时才引入多 Agent 架构——多 Agent 增加复杂度和延迟，不应是默认选项。
